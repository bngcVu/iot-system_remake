**Code thực tế:**
```java
@Transactional
public String sendCommand(DeviceControlDTO dto) {
    Device device = deviceRepo.findById(dto.deviceId())
        .orElseThrow(() -> new IllegalArgumentException("Thiết bị không tồn tại"));

    String correlationId = UUID.randomUUID().toString();
    commandPublisher.sendAction(
        device.getId().intValue(), 
        dto.action().toString(), 
        correlationId
    );

    log.info("[SERVICE] Đã gửi lệnh -> deviceId={}, action={}", 
        device.getId(), dto.action());
    return correlationId;
}
```

### Bước 5: [BE] MqttService publish lệnh lên MQTT Broker

**File:** `Back-end/iot-system/src/main/java/com/iot_system/mqtt/MqttService.java`
- Method: `sendAction(int deviceId, String action, String correlationId)`
- Tạo MQTT topic: `iot/actions`
- Tạo JSON payload với deviceId, action, correlationId
- Publish với QoS = 1

**Code thực tế:**
```java
public void sendAction(int deviceId, String action, String correlationId) {
    JSONObject json = new JSONObject();
    json.put("deviceId", deviceId);
    json.put("action", action);
    json.put("cid", correlationId);
    json.put("ts", System.currentTimeMillis());

    MqttMessage msg = new MqttMessage(json.toString().getBytes());
    msg.setQos(1);

    try {
        client.publish("iot/actions", msg);
        log.info("MQTT PUB -> iot/actions: {}", json);
    } catch (MqttException e) {
        log.error("MQTT publish failed", e);
    }
}
```

  "cid": "abc-123-def",

}
QoS: 1 (At least once delivery)

### Bước 6: [HW] ESP32 subscribe và nhận MQTT message

**File:** `iot_v2.ino` (Arduino/C++ trên ESP32)
- Subscribe topic: `iot/actions`
- Callback function: `mqttCallback(char* topic, byte* payload, unsigned int length)`
- Parse JSON payload bằng ArduinoJson
- Lấy deviceId, action, correlationId
- Thực thi: `digitalWrite(pin, action == "ON" ? HIGH : LOW)`

**Code ví dụ (giả định):**
```cpp
void mqttCallback(char* topic, byte* payload, unsigned int length) {
    StaticJsonDocument<256> doc;
    deserializeJson(doc, payload, length);
    
    int deviceId = doc["deviceId"];
    String action = doc["action"];
    String cid = doc["cid"];
    
    if (deviceId == 1) { // LIGHT
        digitalWrite(LIGHT_PIN, action == "ON" ? HIGH : LOW);
    } else if (deviceId == 2) { // FAN
        digitalWrite(FAN_PIN, action == "ON" ? HIGH : LOW);
    } else if (deviceId == 3) { // AIR
        digitalWrite(AIR_PIN, action == "ON" ? HIGH : LOW);
    }
    
    Serial.println("[HW] Executed: " + action);
    
    // Gửi ACK về Backend
    publishACK(deviceId, action, cid);
}
```

**Physical action:**
```
GPIO PIN = HIGH (3.3V) → Relay ON → Đèn/Quạt/Điều hòa BẬT 💡
GPIO PIN = LOW (0V)    → Relay OFF → Đèn/Quạt/Điều hòa TẮT ⚫
```

```java
@Override
public void messageArrived(String topic, MqttMessage message) throws Exception {
    String payload = new String(message.getPayload());
    log.info("MQTT SUB <- {}: {}", topic, payload);

    if ("iot/acks".equals(topic)) {
        handleDeviceACK(payload);
    } else if ("iot/sensors".equals(topic)) {
        handleSensorData(payload);
    }
}

private void handleDeviceACK(String payload) {
    JSONObject json = new JSONObject(payload);
    int deviceId = json.getInt("deviceId");
    String action = json.getString("action");
    String cid = json.getString("cid");
    
    // Update device state in DB
    deviceService.updateDeviceState(deviceId, action);
    
    // Save action history
    actionHistoryService.saveAction(deviceId, action, LocalDateTime.now());
    
    log.info("[ACK] Device {} -> {}", deviceId, action);
}
```

### Bước 10: [FE] WebSocket nhận ACK từ Backend

**File:** `Back-end/iot-system/src/main/resources/static/js/index.js`
- LƯU Ý: Project DÙNG **WebSocket (STOMP)** cho realtime updates
- Function: `connectWS()` kết nối WebSocket và subscribe topics
- Topic: `/topic/devices` - Nhận ACK khi thiết bị thay đổi trạng thái
- Xử lý ACK với `pendingMap` để match correlation ID

**Code thực tế:**
```javascript
function connectWS() {
  stompClient = connectStomp({
    onDevices: (ack) => {
      try {
        const idx = deviceIdByToggleIndex.findIndex(id => id === ack.deviceId);
        if (idx >= 0) {
          // Match ACK với pending command
          const pend = pendingMap.get(ack.deviceId);
          if (pend) {
            // Validate correlation ID để tránh update nhầm
            if (pend.correlationId && !ack.correlationId) {
              return; // Ignore status push không có cid
            }
            if (pend.correlationId && ack.correlationId && 
                ack.correlationId !== pend.correlationId) {
              return; // Ignore ACK không match
            }
            clearTimeout(pend.timer);
            pendingMap.delete(ack.deviceId);
          }
          
          // Update UI
          const toggle = document.getElementById(`led${idx}-toggle`);
          if (toggle) {
            toggle.checked = ack.state === 'ON';
            toggle.disabled = false;
          }
          
          // Update icon animation
          if (idx === 0) setIconState('light', ack.state === 'ON');
          if (idx === 1) setIconState('fan', ack.state === 'ON');
          if (idx === 2) setIconState('air', ack.state === 'ON');
        }
      } catch {}
    }
  });
}
```

**Khi nhận được ACK (qua WebSocket):**
- Validate correlation ID với `pendingMap`
- Clear timeout rollback timer
- Set `toggle.checked = true/false` theo state
- Enable toggle: `toggle.disabled = false`
- Update icon animation state

### LƯU Ý QUAN TRỌNG:

**TRƯỚC (Client-side counting - ĐÃ BỎ):**
- FE fetch 10,000+ records device actions
- FE fetch 1,500+ records sensor data
- FE loop và đếm từng record (rất chậm)
- Data transfer: ~100KB per page load

**SAU (Server-side counting - HIỆN TẠI):**
- FE chỉ gọi 2 APIs
- BE đếm bằng SQL COUNT (cực nhanh)
- FE nhận kết quả đã đếm sẵn
- Data transfer: ~50 bytes per page load
- Performance: Tăng 90% (từ ~1s → ~100ms)

function recheckAllAlerts() {
  try {
    // Lấy giá trị sensor hiện tại từ UI
    const tempEl = select('box-temp');
    const humEl = select('box-hum');
    const lightEl = select('box-light');
    
    if (!tempEl || !humEl || !lightEl) return;
    
    const currentTemp = parseFloat(tempEl.textContent);
    const currentHum = parseFloat(humEl.textContent);
    const currentLight = parseFloat(lightEl.textContent);
    
    // Tạo object giả để pass vào checkAndApplyAlerts
    const fakeLatest = {
      temperature: Number.isFinite(currentTemp) ? currentTemp : NaN,
      humidity: Number.isFinite(currentHum) ? currentHum : NaN,
      light: Number.isFinite(currentLight) ? currentLight : NaN,
      recordedAt: new Date()
    };
    
    console.log('[Settings] Re-checking alerts with new thresholds:', 
                settings.thresholds);
    console.log('[Settings] Current values:', fakeLatest);
    
    // Gọi lại check alerts (sẽ dùng settings mới)
    checkAndApplyAlerts(fakeLatest);
    
  } catch (e) {
    console.error('[Settings] Error re-checking alerts:', e);
  }
}

### Bước 4: [FE] Centralized alert checking logic

**Function:** `checkAndApplyAlerts(latest)` (dòng 388-446)
- **Single source of truth** cho tất cả alert logic
- So sánh sensor values với `settings.thresholds`
- Apply CSS classes: `alert-hard`, `alert-flash`
- GSAP animations cho visual feedback
- Debounce với `lastFlashAt` để tránh flash spam

**Code:**
```javascript
function checkAndApplyAlerts(latest) {
  if (!latest) return;
  
  // Temperature alert
  const tempCard = select('card-temp');
  if (tempCard && Number.isFinite(latest.temperature)) {
    tempCard.classList.remove('alert-soft', 'alert-hard', 
                               'alert', 'alert-flash');
    
    if (latest.temperature > settings.thresholds.temp) {
      tempCard.classList.add('alert-hard');
      
      const now = performance.now();
      if (now - lastFlashAt.temp > 2000) {
        lastFlashAt.temp = now;
        tempCard.classList.add('alert-flash');
        setTimeout(() => tempCard.classList.remove('alert-flash'), 700);
        
        // Icon pulse animation
        gsap.fromTo('#icon-temp svg', 
          { scale: 1 }, 
          { scale: 1.15, yoyo: true, repeat: 3, duration: 0.15 }
        );
      }
    }
  }
  
  // Humidity alert (tương tự)
  // Light alert (tương tự)
}
```

**Ví dụ thực tế:**
```
Before: Temp = 32°C, Threshold = 30°C → Alert ON (red card)
User changes: Threshold 30°C → 35°C
recheckAllAlerts() executes immediately
After: Temp = 32°C, Threshold = 35°C → Alert OFF (32 < 35)
UI updates instantly: Red card → Normal card
```

### LƯU Ý QUAN TRỌNG:

**TRƯỚC (Alert bug):**
- Alerts chỉ check khi có sensor data mới
- User thay đổi threshold → UI KHÔNG update ngay
- Phải đợi sensor data tiếp theo (5 giây sau)
- Confusing UX: Threshold 35°C nhưng vẫn alert ở 32°C

**SAU (Fixed):**
- User thay đổi threshold → `recheckAllAlerts()` trigger ngay
- Re-evaluate alerts với current sensor values
- UI update INSTANTLY (không cần đợi sensor data)
- Cross-tab sync: Thay đổi ở tab 1 → Tab 2 auto update
- Single source of truth: `checkAndApplyAlerts()` function
- Code cleaner: Removed ~45 lines duplicate code

**Performance:**
- recheckAllAlerts: ~1ms (chỉ đọc DOM)
- checkAndApplyAlerts: ~2ms (CSS + GSAP)
- Total: ~3ms → Instant feedback cho user

**Backend:**

- Language: Java

- Database: JPA/Hibernate với MySQL

**MQTT Broker:**
- Mosquitto (hoặc HiveMQ)
- Topics:
  * `iot/actions` - Backend publish commands
  * `iot/acks` - ESP32 publish ACK
  * `iot/sensors` - ESP32 publish sensor data

**Hardware:**
- ESP32 microcontroller
- Sensors: DHT22 (temp/humidity), LDR (light)
- Actuators: Relay modules điều khiển đèn/quạt/điều hòa
- Code: Arduino/C++

**Database Schema:**
- `device` - Danh sách thiết bị
- `device_action_history` - Lịch sử bật/tắt
- `sensor_data` - Dữ liệu cảm biến
- Indexes: executed_at, recorded_at (for query performance)

**Communication Flow:**
- FE ↔ BE: HTTP REST (JSON) + WebSocket (STOMP/SockJS)
- BE ↔ MQTT: Pub/Sub (QoS 1)
- BE ↔ DB: JPA/JDBC
- FE update: WebSocket realtime + HTTP polling fallback
- Settings: localStorage với cross-tab sync via `storage` event

**Alert System:**
- Thresholds: Stored in localStorage (`iot_settings`)
- Check timing: 
  * On new sensor data (WebSocket)
  * On settings change (instant re-check)
  * On cross-tab sync (storage event)
- Visual feedback: CSS classes + GSAP animations
- Debounce: 2 seconds between flash animations
